Research Mind Map Manual

Detailed guide for the local research mapping prototype, including workflows, integrations, storage, sharing, troubleshooting, and roadmap notes.

Overview

The app is a local browser-based research mapping and literature-review prototype. The frontend is plain HTML, CSS, and JavaScript. The backend is FastAPI and enables local-only features such as Zotero, PDF opening and annotation extraction, image saving, GROBID analysis, file autosaves, snapshots, and project workspaces.

Current Feature Summary

  • Visual mind map with typed nodes and directed connections.
  • Configurable node types with editable colors.
  • Protected default node types: Publication, Idea, and Unassigned.
  • Right-click node actions for editing, connecting, duplicating, links, ordering, type changes, style copy/paste, and deletion.
  • Undo for graph edits with Ctrl+Z or Command+Z.
  • Application-wide search for nodes, connections, notes, citations, URLs, tags, and metadata.
  • Project workspaces with server autosaves, snapshots, and JSON backup/import.
  • Local integrations for Zotero, PDFs, note images, and GROBID.

Views And Projects

The toolbar has three workspace modes: Map, Document, and Multi View. Map shows the visual mind map with the right-side details panel. Document shows a writing workspace linked to map nodes and connections. Multi View shows map and document side by side.

The project selector switches between project folders. Each project has its own latest autosave, snapshots, copied PDFs, note images, and deleted-image archive. Switching projects loads that project's latest server autosave when the FastAPI backend is running.

The document outline can group by currently used node types or by connections. Ideas and publications are grouped by document tag. Connections are grouped by first tag and are shown with short labels such as Connection 1, Connection 2, or Citation connection.

Clustering

The map can cluster by tags, authors, or number of connections. Tag clustering uses the first tag by default and can draw configurable background circles with tag labels. In single-tag mode, connected nodes from other clusters are nudged toward relevant cluster edges to make cross-cluster links easier to read.

Author clustering counts every listed publication author, normalizes names by first and last name, and uses an author-frequency threshold to avoid one-paper author clusters. Low-frequency papers are placed into an Other authors area.

Connection-count clustering groups nodes by how many map connections they have, which helps identify central and isolated nodes.

Map Details Panel

Selecting a node opens details for title, type, URL, publication citation, tags, notes, links, PDF opening, and PDF annotation import. The formatting tab supports node size, font size, font family, font style, and style copy/paste. Multi-select formatting is supported for node size and text style changes.

Selecting a connection opens connection details: label, source node, target node, notes, tags, global arrow color, and global arrow thickness. When a connection is selected, both endpoint nodes are highlighted on the map.

Document Editor

The document editor is a prototype word-processor-style interface linked to map nodes and connections. It supports font family, font size, paragraph style, bold, italic, underline, format painter, text color, highlight color, lists, alignment, hyperlinks, node links, images, tables, and URL auto-linking.

Publication pages include notes plus citation and URL metadata. Idea pages are plain note pages. Connection pages show compact From and To metadata above the editable connection note. Node links are grouped by tag in the node-link picker and can be filtered by search and node type.

Zotero Integration

Zotero integration requires the FastAPI backend and Zotero Desktop running locally. The backend first tries Zotero Desktop's local API at http://localhost:23119/api/. If needed, it can inspect the local Zotero data directory.

Windows: C:\Users\<your-username>\Zotero
macOS/Linux: ~/Zotero

You can set ZOTERO_DATA_DIR if your Zotero directory is custom. Imported publication nodes can store Zotero item key, title, authors, year, DOI, citation, URL, abstract, and tags.

GROBID Citation Analysis

GROBID is used to find citation relationships between publications already in the map. Expected local setup:

Docker image: grobid/grobid:0.9.0-full
Container name: grobid
Service URL: http://127.0.0.1:8070
Health endpoint: GET /api/isalive
Reference endpoint: POST /api/processReferences

Workflow: import publications from Zotero, make sure they have local PDF attachments, open GROBID, check the service, analyze all publications, review suggestions, and add selected citation links. The app does not automatically create citation edges without review.

Added citation edges include citation and GROBID tags, connection notes, confidence metadata, and match reasoning. Existing citation connections are filtered out to avoid duplicate edges.

Local PDF Workflow

For Zotero-backed publication nodes, PDFs are copied from Zotero into autosaves/{project}/library_pdfs/. The copy is done once. If a copied PDF already exists, the app opens the existing copy and does not overwrite it, protecting annotations and notes.

PDF actions include opening the project copy in the system default PDF viewer, opening the project PDF folder, and importing annotations. Annotation extraction uses PyMuPDF and can extract highlights, highlight comments, standalone comments, and free-text annotations. Adobe-style annotations usually work best.

Images In Notes

Images inserted into document notes are saved through the backend into autosaves/{project}/document_images/. The document stores links to saved image files instead of keeping large base64 images in browser storage. Pasted and dropped images use the same save path.

When a project loads, the backend reconciles note images by saving embedded base64 images as files, migrating old root-level references into the active project when possible, reporting stale unused images, and reporting missing references. Deleted note images are archived under autosaves/{project}/document_images_deleted/.

Saving And Backups

The app uses browser localStorage for lightweight fallback state, project-specific latest autosaves, manual snapshots, JSON export, and JSON import. Server-side folder autosave is the main working save path and avoids browser quota issues when notes include images.

autosaves/{project}/
  research-map-latest.json
  snapshots/
  document_images/
  document_images_deleted/
  library_pdfs/

Manual snapshots are written as timestamped JSON files under autosaves/{project}/snapshots/. Use Reset View only to refit the visible workspace; it does not delete data.

Private Sharing And Presence

The app can be shared privately across trusted devices through Tailscale. Tailscale is not configured inside the repo and no secrets should be committed.

python -m uvicorn server:app --host 127.0.0.1 --port 8000
tailscale serve http://127.0.0.1:8000

The toolbar presence indicator shows how many browser sessions have the same project open. Each tab gets a temporary client ID in sessionStorage and sends a heartbeat about every 15 seconds. The backend keeps recent viewers for about 45 seconds, and the browser also sends a best-effort leave signal when a tab closes.

Presence Troubleshooting

Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/presence" | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/presence/debug" | ConvertTo-Json -Depth 5

Security Notes

  • Tailscale is private networking, not app-level authentication.
  • The prototype has no login, roles, read-only mode, edit locks, or conflict resolution.
  • A trusted collaborator can edit and delete project data reachable through the app.
  • Zotero, GROBID, and PDF actions run on the host machine where FastAPI is running.
  • Simultaneous editing is last-save-wins. Create a snapshot before a shared session.
  • Keep Uvicorn bound to 127.0.0.1:8000 unless you intentionally choose a broader network setup.

Files And Repository Data

  • index.html - page structure, toolbar, panels, document workspace, and modals.
  • style.css - layout and visual styling.
  • app.js - graph behavior, document editor, autosave, import/export, and frontend integration logic.
  • server.py - FastAPI backend for serving the app, Zotero, PDFs, images, autosaves, snapshots, and GROBID analysis.
  • requirements.txt - backend Python dependencies.
  • autosaves/ - project folders with latest autosaves, snapshots, copied PDFs, note images, and deleted-image archives.

The repo keeps folder placeholders and the committed Demo starter save, but ignores private project autosaves, snapshots, copied PDFs, note images, exported JSON files, logs, and local environment files.

Offline Note And Roadmap

The app currently loads Cytoscape.js from a CDN at https://unpkg.com/cytoscape@3.29.2/dist/cytoscape.min.js. Zotero and GROBID integrations are local-first, but Cytoscape can later be vendored locally for fully offline use.

  • Add WebSocket update notifications for trusted shared sessions.
  • Add optional edit locks or read-only viewer mode.
  • Add local LLM support through Ollama or LM Studio for summaries, tag suggestions, and drafted connection notes.
  • Add safer collaboration conflict handling and per-user edit history.
  • Add optional browser-based PDF viewing/download for remote Tailscale users.
  • Explore Local Citation Network-style publication finding with keyword and citation filters.
