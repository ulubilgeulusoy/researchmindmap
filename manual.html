Research Mind Map Manual

Detailed guide for the local research mapping prototype, including workflows, integrations, storage, sharing, troubleshooting, and roadmap notes.

Overview

The app is a local browser-based research mapping and literature-review prototype. The frontend is plain HTML, CSS, and JavaScript. The backend is FastAPI and enables local-only features such as OpenAlex discovery, Zotero, PDF opening and annotation extraction, image saving, GROBID analysis, file autosaves, snapshots, and project workspaces.

Current Feature Summary

  • Visual mind map with typed nodes and directed connections.
  • Configurable node types with editable colors.
  • Protected default node types: Publication, Idea, and Unassigned.
  • Right-click node actions for editing, connecting, duplicating, links, ordering, type changes, style copy/paste, and deletion.
  • Undo for graph edits with Ctrl+Z or Command+Z.
  • Application-wide search for nodes, connections, notes, citations, URLs, tags, and metadata.
  • Project workspaces with server autosaves, snapshots, and JSON backup/import.
  • OpenAlex discovery for related papers and citation-direction searches.
  • Local integrations for Zotero, PDFs, note images, and GROBID.

Getting Started

A typical first-use workflow is:

  1. Create a new project or select an existing project from the Project control.
  2. Add an Idea node manually to capture a concept, question, theme, or hypothesis.
  3. Add a Publication node manually, or import publications from Zotero if Zotero Desktop is available.
  4. Use OpenAlex discovery to find related papers, papers that cite selected publications, or papers cited by selected publications.
  5. Connect related ideas and publications on the map.
  6. Open Document or Multi View to write notes linked to the selected node or connection.
  7. Click Save when you want to create a timestamped recovery snapshot.
  8. Use Export periodically to download a separate JSON backup.

OpenAlex, Zotero, and GROBID are central to the publication workflow: OpenAlex supports discovery, Zotero manages the research library and publication-node import, and GROBID helps identify citation links from local PDFs.

Views and Projects

The toolbar has three workspace modes: Map, Document, and Multi View. Map shows the visual mind map with the right-side details panel. Document shows a writing workspace linked to map nodes and connections. Multi View shows map and document side by side.

The project selector switches between project folders. Each project has its own latest autosave, snapshots, copied PDFs, note images, and deleted-image archive. Switching projects loads that project's latest server autosave when the FastAPI backend is running.

The document outline can group by currently used node types or by connections. Ideas and publications are grouped by document tag. Connections are grouped by first tag and are shown with short labels such as Connection 1, Connection 2, or Citation connection.

Clustering

The map can cluster by tags, authors, or number of connections. Tag clustering uses the first tag by default and can draw configurable background circles with tag labels. In single-tag mode, connected nodes from other clusters are nudged toward relevant cluster edges to make cross-cluster links easier to read.

Author clustering counts every listed publication author, normalizes names by first and last name, and uses an author-frequency threshold to avoid one-paper author clusters. Low-frequency papers are placed into an Other authors area.

Connection-count clustering groups nodes by how many map connections they have, which helps identify central and isolated nodes.

Map Details Panel

Selecting a node opens details for title, type, URL, publication citation, tags, notes, links, PDF opening, and PDF annotation import. The formatting tab supports node size, font size, font family, font style, and style copy/paste. Multi-select formatting is supported for node size and text style changes.

Selecting a connection opens connection details: label, source node, target node, notes, tags, global arrow color, and global arrow thickness. When a connection is selected, both endpoint nodes are highlighted on the map.

Jodit

The document workspace uses the vendored Jodit rich-text editor as its main editing surface. It supports font family, font size, paragraph style, bold, italic, underline, strikethrough, text color, lists, alignment, hyperlinks, node links, images, tables, undo/redo, and URL auto-linking.

Publication pages include notes plus citation and URL metadata. Idea pages are plain note pages. Connection pages show compact From and To metadata above the editable connection note. Node links are grouped by tag in the node-link picker and can be filtered by search and node type.

Jodit assets are stored locally under vendor/jodit-4.2.47/, so the editor does not depend on a Jodit CDN at runtime.

OpenAlex Discovery

OpenAlex is used as a discovery tool, not as the canonical publication library. The app can search OpenAlex works directly, or use selected publication nodes as seed papers to find related literature. OpenAlex results are shown with DOI, OpenAlex, source, PDF, and copy actions when those links are available.

The intended workflow is to discover papers with OpenAlex, open the DOI or source link, save useful papers into Zotero with Zotero Connector, then import those Zotero items into this app as publication nodes. This keeps Zotero as the source of truth for item metadata, local PDFs, and later PDF/GROBID workflows.

Finding Papers From Seed Publications

  1. Import or create publication nodes on the map.
  2. Open Sources, then OpenAlex.
  3. Use the Seed Publications list to check one or more map publication nodes. The filter box can narrow long publication lists.
  4. Choose one or more discovery modes: Related papers, Papers that cite selected, or Papers cited by selected.
  5. Click Find Similar and review the OpenAlex Results pane.
  6. Open DOI, Source, OpenAlex, or PDF links for promising papers.
  7. Use Zotero Connector in the browser to save the paper into Zotero.
  8. Return to this app, open Sources, then Zotero, and import the newly saved Zotero items as publication nodes.

Discovery Modes

  • Related papers uses OpenAlex's broader related-work relationship. These results may be topically relevant without a direct citation relationship.
  • Papers that cite selected finds downstream papers whose references include the selected seed paper.
  • Papers cited by selected finds papers listed in the selected seed paper's references.

For seed-based discovery, each result includes a relationship section comparing the found paper against each selected seed paper. It can say that the found paper cites the selected paper, that the selected paper cites the found paper, or that no direct citation relationship was found. OpenAlex reference coverage can be incomplete, so citation labels should be treated as metadata guidance rather than a final bibliographic audit.

You can also use the top OpenAlex search box for direct keyword search. Direct search results are discovery-only and are not automatically tied to selected seed papers.

Zotero Integration

Zotero integration requires the FastAPI backend and Zotero Desktop running locally. The backend first tries Zotero Desktop's local API at http://localhost:23119/api/. If needed, it can inspect the local Zotero data directory.

Windows: C:\Users\<your-username>\Zotero
macOS/Linux: ~/Zotero

You can set ZOTERO_DATA_DIR if your Zotero directory is custom. Imported publication nodes can store Zotero item key, title, authors, year, DOI, citation, URL, abstract, and tags.

GROBID Citation Analysis

GROBID is used to find citation relationships between publications already in the map. It runs as a separate local service, usually through Docker, and this app calls it at http://127.0.0.1:8070.

Docker Setup

Install Docker Desktop or Docker Engine first, then pull and run the GROBID full image:

docker pull grobid/grobid:0.9.0-full
docker run --name grobid --rm -p 8070:8070 grobid/grobid:0.9.0-full

Keep that terminal running while using citation analysis. If you prefer a detached background container, use:

docker run --name grobid -d -p 8070:8070 grobid/grobid:0.9.0-full

When running detached, stop it with:

docker stop grobid

Expected Service

Docker image: grobid/grobid:0.9.0-full
Container name: grobid
Service URL: http://127.0.0.1:8070
Health endpoint: GET /api/isalive
Reference endpoint: POST /api/processReferences

You can check the service outside the app with:

curl http://127.0.0.1:8070/api/isalive

On Windows PowerShell, use:

Invoke-RestMethod -Uri "http://127.0.0.1:8070/api/isalive"

App Workflow

Import publications from Zotero, make sure they have local PDF attachments, open the GROBID panel, click Check GROBID, analyze all publications, review suggestions, and add selected citation links. The app does not automatically create citation edges without review.

Added citation edges include citation and GROBID tags, connection notes, confidence metadata, and match reasoning. Existing citation connections are filtered out to avoid duplicate edges.

Common Issues

  • If Check GROBID fails, confirm Docker is running and port 8070 is not blocked or already used by another service.
  • The first GROBID startup can take time because the full service loads models before it is ready.
  • Citation suggestions depend on PDF quality. Scanned PDFs or malformed references may produce few or no matches.
  • GROBID analysis runs on the machine hosting FastAPI. A remote browser user does not run GROBID on their own computer.

Local PDF Workflow

For Zotero-backed publication nodes, PDFs are copied from Zotero into autosaves/{project}/library_pdfs/. The copy is done once. If a copied PDF already exists, the app opens the existing copy and does not overwrite it, protecting annotations and notes.

PDF actions include opening the project copy in the system default PDF viewer, opening the project PDF folder, and importing annotations. Annotation extraction uses PyMuPDF and can extract highlights, highlight comments, standalone comments, and free-text annotations. Adobe-style annotations usually work best.

Images in Notes

Images inserted into document notes are saved through the backend into autosaves/{project}/document_images/. The document stores links to saved image files instead of keeping large base64 images in browser storage. Pasted and dropped images use the same save path.

When a project loads, the backend reconciles note images by saving embedded base64 images as files, migrating old root-level references into the active project when possible, reporting stale unused images, and reporting missing references. Deleted note images are archived under autosaves/{project}/document_images_deleted/.

Saving and Backups

The app uses browser localStorage for lightweight fallback state, project-specific latest autosaves, manual snapshots, JSON export, and JSON import. Server-side folder autosave is the main working save path and avoids browser quota issues when notes include images.

Autosave continuously updates autosaves/{project}/research-map-latest.json. This is the main working file that the app reloads when you open or switch to a project.

Save does not replace autosave. The Save button creates an additional timestamped snapshot under autosaves/{project}/snapshots/ so you have a recovery point from that moment.

autosaves/{project}/
  research-map-latest.json
  snapshots/
  document_images/
  document_images_deleted/
  library_pdfs/

Use Export periodically to download a separate JSON backup outside the autosave folder. Use Reset View only to refit the visible workspace; it does not delete data.

Recovery Options

  1. Use Import to restore a previously exported JSON backup through the app interface.
  2. Use a manual snapshot from autosaves/{project}/snapshots/ as a recovery point.
  3. To recover from a snapshot directly, stop the FastAPI server first so autosave cannot overwrite files while you are replacing them.
  4. Copy the selected snapshot JSON and rename the copy to research-map-latest.json in the relevant project folder.
  5. Restart the FastAPI server, reload the app, and select the project.

Direct snapshot replacement is supported because manual snapshots and latest autosaves use the same JSON structure: saved timestamp, project name, node types, and graph elements.

Private Sharing and Presence

The app can be shared privately across trusted devices through Tailscale. Tailscale is not configured inside the repo and no secrets should be committed.

Recommended Tailscale Flow

  1. Install Tailscale on the host machine and sign in.
  2. Start this app's FastAPI backend from the project folder on the host machine: 
    python -m uvicorn server:app --host 127.0.0.1 --port 8000
    The host machine is the computer that runs server.py and stores the local project files, OpenAlex/Zotero/PDF/GROBID access, image saves, autosaves, and presence state.
  3. Expose that local FastAPI app through Tailscale Serve: 
    tailscale serve http://127.0.0.1:8000
  4. Open the private HTTPS URL that Tailscale prints from another trusted device in the same Tailnet or an explicitly shared device/user: 
    https://your-device.your-tailnet.ts.net/

Keep Uvicorn bound to 127.0.0.1. Tailscale Serve can safely forward the private HTTPS endpoint to that local-only backend without making FastAPI listen on the public network.

Access-Control Guidance

If you share the host machine with an external collaborator, restrict their Tailscale access to the app endpoint instead of granting broad access to the whole machine. Tailscale Serve exposes HTTPS on TCP 443, then forwards internally to 127.0.0.1:8000.

{
  "src": ["autogroup:shared"],
  "dst": ["YOUR_DEVICE_TAILSCALE_IP_OR_DEVICE_SELECTOR"],
  "ip": ["tcp:443"]
}

Use your host device's Tailscale IP or the device selector accepted by the Tailscale policy editor. You can find the host Tailscale IPv4 address with:

tailscale ip -4

Avoid granting shared users access to all ports and protocols unless you intentionally want them to reach other services on the host machine.

The toolbar presence indicator shows how many browser sessions have the same project open. Each tab gets a temporary client ID in sessionStorage and sends a heartbeat about every 15 seconds. The backend keeps recent viewers for about 45 seconds, and the browser also sends a best-effort leave signal when a tab closes.

Security Notes

  • Tailscale is private networking, not app-level authentication.
  • The prototype has no login, roles, read-only mode, edit locks, or conflict resolution.
  • A trusted collaborator can edit and delete project data reachable through the app.
  • OpenAlex, Zotero, GROBID, and PDF actions run on the host machine where FastAPI is running.
  • Simultaneous editing is last-save-wins. Create a snapshot before a shared session.
  • Keep Uvicorn bound to 127.0.0.1:8000 unless you intentionally choose a broader network setup.

Files and Repository Data

  • index.html - page structure, toolbar, panels, document workspace, and modals.
  • style.css - layout and visual styling.
  • app.js - graph behavior, document editor, autosave, import/export, and frontend integration logic.
  • server.py - FastAPI backend for serving the app, OpenAlex, Zotero, PDFs, images, autosaves, snapshots, and GROBID analysis.
  • requirements.txt - backend Python dependencies.
  • autosaves/ - project folders with latest autosaves, snapshots, copied PDFs, note images, and deleted-image archives.
  • vendor/jodit-4.2.47/ - local Jodit rich-text editor assets used by the document workspace.

The repo keeps folder placeholders and the committed Demo starter save, but ignores private project autosaves, snapshots, copied PDFs, note images, exported JSON files, logs, and local environment files.

Potential Improvements

The app currently loads Cytoscape.js from a CDN at https://unpkg.com/cytoscape@3.29.2/dist/cytoscape.min.js. Jodit editor assets are already vendored locally under vendor/jodit-4.2.47/. Zotero and GROBID integrations are local-first, OpenAlex requires internet access from the FastAPI host, and Cytoscape can later be vendored locally for more offline use.

  • Add WebSocket update notifications for trusted shared sessions.
  • Add optional edit locks or read-only viewer mode.
  • Add local LLM support through Ollama or LM Studio for summaries, tag suggestions, and drafted connection notes.
  • Add safer collaboration conflict handling and per-user edit history.
  • Add optional browser-based PDF viewing/download for remote Tailscale users.
  • Expand OpenAlex discovery with additional filters, paging, and local citation-network-style exploration.
